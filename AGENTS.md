# AGENTS.md

Правила для AI-агентов, работающих в этом репозитории.

## Обзор репозитория

Репозиторий содержит **Agent Skills** — портативные пакеты навыков по открытому стандарту
[Agent Skills](https://agentskills.io). Сейчас в нём один навык — `sape-links-seo`: покупка
SEO-статей и ссылочных размещений на площадках-донорах через платформу
[Sape](https://sape.ru).

Одновременно репозиторий служит **маркетплейсом плагинов Claude** (`.claude-plugin/`),
поэтому у него две аудитории: агенты, устанавливающие навык ZIP-архивом, и Claude Code,
ставящий плагин.

- **Название**: Sape Links SEO
- **GitHub**: [sape-ru/agents-skill-sape](https://github.com/sape-ru/agents-skill-sape)
- **Владелец**: Sape ([sape.ru](https://sape.ru))
- **Лицензия**: файла LICENSE в репозитории нет. Не придумывайте лицензию и не добавляйте её
  без явной просьбы.
- **Язык**: документация, навык и заметки релизов — русский; коммиты — английский.

## Проверки и сборка

Тестов, линтеров и отдельной сборки нет: скрипты написаны на чистом Python (только stdlib),
в CI используется Python 3.12. Все автоматические проверки запускаются этими командами:

```bash
python3 scripts/package_skill.py --version            # сверить версии и напечатать её
python3 scripts/package_skill.py                      # собрать 4 ZIP-архива в dist/
python3 scripts/package_skill.py --output /tmp/out    # собрать в другую папку
python3 scripts/check_versions.py --base origin/main  # то же, что проверка на PR
```

`package_skill.py` проверяет, что версия совпадает в `SKILL.md`, `.claude-plugin/plugin.json`
и `.claude-plugin/marketplace.json`, что `description` в `SKILL.md` не длиннее 1024 символов,
а `packaging/claude-web-description.txt` — одной строкой не длиннее 200 символов.

`check_versions.py` дополнительно требует, чтобы таблица и раздел `### X.Y.Z (дата)` в
`VERSIONS.md` соответствовали текущей версии, и чтобы PR, меняющий `skills/**` или
`packaging/**`, поднимал версию относительно base.

Проверки, которых нет автоматически и которые делаются глазами:

- JSON в `.claude-plugin/` валиден — `python3 -c "import json; json.load(open('.claude-plugin/plugin.json'))"`
  (и то же для `marketplace.json`).
- YAML workflow-файлов ничем не валидируется: после правок в `.github/workflows/` нужен
  пробный запуск (PR или `workflow_dispatch`).
- Каждый файл в `references/` упомянут в `SKILL.md` — иначе агент его не прочитает.
  Сейчас `references/placement_actions.md` связан из раздела «Управление размещениями».

## Версионирование

Версия у репозитория одна — она же версия навыка. Хранится в четырёх местах и должна
совпадать везде:

| Место | Поле |
|---|---|
| `skills/sape-links-seo/SKILL.md` | `version` во frontmatter |
| `.claude-plugin/plugin.json` | `version` |
| `.claude-plugin/marketplace.json` | `version` у плагина `sape-links-seo` |
| `VERSIONS.md` | строка навыка в таблице |

Правила semver для этого репозитория:

- **x (major)** — ломающее изменение контракта навыка: переименование или удаление
  инструментов, изменение обязательных шагов workflow, форматов размещений, несовместимое
  с прежними инструкциями.
- **y (minor)** — новая возможность: новый сценарий (например, работа с Избранным), новый
  формат, заметное расширение фильтров поиска.
- **z (patch)** — исправления, уточнения формулировок, оформление, обновление ссылок.

Жёсткие правила:

1. Версия поднимается **в том же PR**, что и изменение навыка или упаковки. Отдельным
   «догоняющим» PR — нельзя.
2. Источник истины — `plugin.json`; остальные три места скрипт сверяет с ним.
3. Теги ставит **только** релизный workflow. Не создавайте теги вручную (`git tag`,
   `git push --tags`) и не двигайте существующие: архивы собираются из коммита тега, поэтому
   сдвинутый тег выпустит не тот код.
4. `VERSIONS.md` — публичный текст: пишите для пользователей навыка, без внутренних имён и
   служебных подробностей. Первая строка раздела становится заголовком релиза, поэтому она
   должна читаться как законченная мысль.

## Релизный конвейер

`release.yml` запускается на push в `main`, если изменился один из путей:
`.claude-plugin/plugin.json`, `.claude-plugin/marketplace.json`, `skills/**`, `packaging/**`,
`VERSIONS.md`. Есть и ручной запуск — `workflow_dispatch`, например чтобы пересобрать архивы.

Порядок шагов:

1. **Проверка невыпущенных изменений.** Если тег текущей версии уже существует, но после него
   менялись `skills/` или `packaging/`, запуск падает со списком забытых файлов. Это значит,
   что версию не подняли и пользователи релизов изменений не получат.
2. **Определение версии.** Версия берётся из `plugin.json`.
3. **Тег.** Если тега `vX.Y.Z` нет — он создаётся на текущем коммите. Если есть — тег не
   двигается, архивы собираются из коммита тега.
4. **Заметки и заголовок.** Берутся из раздела `### X.Y.Z (дата)` в `VERSIONS.md` на коммите
   релиза. Заголовок — `vX.Y.Z — <первая строка раздела>` с обрезкой до 100 символов. Если
   раздела нет, тело релиза будет заглушкой `Release X.Y.Z` — это деградация, а не ошибка.
5. **Архивы и публикация.** Собираются 4 ZIP из коммита релиза, создаётся релиз (если его нет)
   и архивы загружаются с `--clobber`, поэтому повторный запуск безопасен и заменяет ассеты.

`check-versions.yml` работает на PR (кроме draft и `dependabot`) и публикацией не управляет:
запускает `check_versions.py` и сборку архивов «вхолостую».

Изменения попадают в `main` только через PR. Required status checks при этом не включены:
workflow запускается по путям, и PR без правок в навыке не отчитался бы статусом. Поэтому
PR-проверка — обязательный шаг процесса, а не блокировка merge. Если прямой push всё же
случился, единственная страховка — шаг 1 релизного workflow.

## Стандарт Agent Skills

Навык следует [спецификации Agent Skills](https://agentskills.io/specification).

### Обязательный frontmatter

```yaml
---
name: sape-links-seo
version: 1.2.1
description: Что делает навык и в каких ситуациях его подключать.
---
```

| Поле | Обязательно | Ограничения в этом репозитории |
|---|---|---|
| `name` | да | 1–64 символа, `a-z`, цифры и дефисы, совпадает с именем каталога |
| `description` | да | 1–1024 символа (стандарт), должен объяснять **когда** использовать навык |
| `version` | да | `X.Y.Z`; расширение этого репозитория, стандарт его не требует |

Правила `name`: только нижний регистр, цифры и дефисы; не начинается и не заканчивается
дефисом; без `--`; совпадает с именем родительского каталога.

Допустимо: `sape-links-seo`. Недопустимо: `Sape-Links-SEO`, `-sape`, `sape--links`.

### Опциональные каталоги навыка

```
skills/sape-links-seo/
├── SKILL.md        # обязательный: frontmatter + инструкции
├── references/     # подробные справочники, читаются по требованию
├── scripts/        # исполняемый код (сейчас нет)
└── assets/         # шаблоны и данные (сейчас нет)
```

`SKILL.md` держите компактным: детали, таблицы статусов и длинные перечни выносите в
`references/` и ссылайтесь на файл из тела `SKILL.md`. Сейчас `SKILL.md` — около 540 строк;
уменьшать его можно только вместе с переносом содержимого в `references/`, не теряя правил.

## Правила письма

- Язык навыка и документации — **русский**; коммиты — английский.
- Тон: прямо и по делу, императив для инструкций агенту («вызовите», «проверьте»),
  обращение на «вы» для текстов о пользователе.
- Таблицы — для сравнений, статусов, аргументов инструментов. Списки — для шагов.
- Суммы — только в рублях (₽). Арендные цены всегда помечайте как **цену за месяц**.
- Имена инструментов и полей — в бэктиках, в «голом» виде: `get_user_info`, а не
  `mcp__sape__get_user_info` (префикс зависит от хост-агента).
- Пара `❌` / `✅` допустима в антипаттернах. Другие эмодзи не используйте.
- Не добавляйте в навык обещаний, которых нет в API: если поведение неизвестно, проверьте
  его или напишите осторожнее.

### Про `description`

`description` — главный механизм обнаружения навыка. В нём должно быть: что навык делает,
в каких ситуациях его подключать (словами пользователя, а не списком синонимов) и, если есть,
жёсткое правило, которое должно сработать до чтения тела.

При изменении `description` в `SKILL.md` обновите и `packaging/claude-web-description.txt` —
короткое описание для claude.ai (≤ 200 символов, одна строка). Оно подменяет `description`
в архиве `sape-links-seo-claude-web.zip`.

## MCP и финансовые ограничения

Всё взаимодействие с платформой идёт через Sape Links MCP — размещённый streamable HTTP
сервер: `https://mcp-links.sape.ru/mcp`. Аутентификация — OAuth при первом обращении,
инструмент `authorize` вызывается сервером автоматически, вручную его дёргать не нужно.
Подключение описано в `.mcp.json` (плагин) и в README (ручная установка).

**Абсолютные запреты для агентов, работающих с этим репозиторием:**

- Не вызывайте `purchase_placement`, `purchase_rent_placement` и `perform_placement_action`
  в тестах, проверках или «для проверки конвейера» — это реальные деньги пользователя.
- Не коммитьте токены, cookies, логины, номера проектов и любые данные аккаунта: репозиторий
  публичный. В тексте навыка не должно быть примеров с настоящими идентификаторами.
- Не пытайтесь пополнять баланс программно. Пополнение — только через
  <https://passport.sape.ru/deposit/>, пользователем вручную.

Правила, которые навык обязан соблюдать и которые нельзя ослаблять при правках: перед любой
покупкой или действием с деньгами агент показывает цену, текущий баланс и остаток после
покупки и запрашивает явное подтверждение. Для аренды дополнительно проговаривается, что
платёж рекуррентный. Это ядро навыка, а не украшение.

## Плагин Claude Code

Репозиторий — маркетплейс плагинов: `.claude-plugin/marketplace.json` (имя `sape`) описывает
плагин `sape-links-seo`, чей `source` — корень репозитория. `.mcp.json` подключает MCP-сервер
вместе с плагином.

```bash
/plugin marketplace add sape-ru/agents-skill-sape
/plugin install sape-links-seo@sape
```

Плагины сторонних маркетплейсов не обновляются автоматически — обновление вручную через
`/plugin` → **Update now** или `claude plugin update sape-links-seo@sape`.

Важно для документации: на claude.ai и в Claude Desktop установка плагина **не подключает**
MCP-сервер автоматически. Коннектор появляется в состоянии «Not added», его нужно добавить и
подключить на вкладке **Connectors** карточки плагина. В Claude Code OAuth запускается при
первом обращении к инструментам.

## Упаковка и архивы

`package_skill.py` собирает 4 архива — по два содержимого в двух именах:

| Архив | Содержимое |
|---|---|
| `sape-links-seo-<версия>.zip` | исходный навык без изменений |
| `sape-links-seo.zip` | то же, для постоянной ссылки `releases/latest/download/...` |
| `sape-links-seo-claude-web-<версия>.zip` | то же, но с коротким `description` из `packaging/` |
| `sape-links-seo-claude-web.zip` | то же, для постоянной ссылки |

Требования к архивам: папка навыка — **корень** архива (как требует стандарт), дата файлов
фиксирована (одинаковый исходник даёт одинаковый архив), `dist/` в `.gitignore` и в
репозиторий не попадает. Архивы собираются только из `skills/sape-links-seo/`, поэтому
правки README, AGENTS.md и скриптов на содержимое релиза не влияют.

## Git-процесс

Имена веток:

- `feat/<что>` — новая возможность навыка;
- `fix/<что>` — исправление;
- `docs/<что>` — документация;
- `chore/<что>` — инфраструктура, workflow, скрипты.

Сообщения коммитов — [Conventional Commits](https://www.conventionalcommits.org/) на
английском: `feat: add favorites lists`, `fix: correct rent placement statuses`,
`docs: add AGENTS.md`, `chore: bump actions to v6`.

Чеклист перед PR:

- [ ] Версия поднята одинаково в `SKILL.md`, `plugin.json`, `marketplace.json`, `VERSIONS.md`
      (если менялись `skills/**` или `packaging/**`)
- [ ] В `VERSIONS.md` есть раздел `### X.Y.Z (дата)`, его первая строка годится в заголовок
- [ ] Короткое описание для claude.ai обновлено, если менялся `description`
- [ ] JSON в `.claude-plugin/` валиден
- [ ] Каждый файл из `references/` упомянут в `SKILL.md`
- [ ] Нет секретов, токенов и реальных идентификаторов аккаунта
- [ ] `python3 scripts/check_versions.py --base origin/main` проходит

## Проверка обновлений

`VERSIONS.md` — публичная точка сверки версий: агенты могут сравнить указанную там версию с
локальной копией навыка. Если добавляете инструкции про обновление в навык или README,
используйте этот файл, а не `plugin.json`:

```bash
curl -fsSL https://raw.githubusercontent.com/sape-ru/agents-skill-sape/main/VERSIONS.md
```

Обновление пользователь делает сам: `git pull` (если репозиторий склонирован) или повторная
установка архива/плагина. Не обещайте автообновление — у сторонних маркетплейсов его нет.

## Только для Claude Code

Claude Code поддерживает динамическую подстановку команд через `` !`command` `` в `SKILL.md`.
**Не используйте этот синтаксис в навыке**: другие агенты увидят литеральную строку вместо
результата, и инструкция станет мусором. Если такая подстановка нужна, применяйте её только
в локальных оверрайдах проекта, а не в файлах этого репозитория.

`CLAUDE.md` в корне — тонкая обёртка: импорт `@AGENTS.md` и три пункта про Claude Code.
Своих правил в нём не держим, чтобы инструкции не начали противоречить `AGENTS.md`.
