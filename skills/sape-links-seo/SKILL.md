# Sape Links SEO — покупка статей и ссылочных размещений

## Обзор

Этот навык ведёт агента через линкбилдинг на платформе [Sape](https://sape.ru): создание проектов для продвигаемых сайтов, поиск площадок-доноров, загрузка статей или URL-ов с анкорами, покупка размещений и управление их жизненным циклом.

В Sape все расчёты ведутся в рублях (₽). Всем упоминания цен будут только в рублях.

Платформа поддерживает **два типа размещений**:

- **Статейные** — разовая оплата. Форматы: гостевой пост (`news`), обзор (`review`), ссылка в новости (`link`), ссылка в архиве (`archive`).
- **Арендные** — помесячная оплата. Формат: арендная ссылка (Niche Edit). Отдельная база доноров, упрощённый жизненный цикл.

Сущности **проект**, **URL** и **анкорный текст** — общие для обоих типов. Всё взаимодействие с платформой происходит исключительно через **Sape Links MCP-сервер**, который пользователь подключает самостоятельно. Приложение Sape Links доступно по адресу [https://api-links.sape.ru](https://api-links.sape.ru).

## Предварительные требования

- Аккаунт **рекламодателя** в Sape. API-токен создаётся в разделе [Паспорт → Безопасность](https://passport.sape.ru/security/token/).
- **Sape Links MCP-сервер**, подключённый к агенту по адресу `https://mcp-links.sape.ru/mcp`. Аутентификация выполняется сервером через встроенный OAuth-поток — при подключении пользователь указывает только URL. Никаких Docker, Node.js или CLI не требуется.

## Как отображаются имена инструментов

MCP-сервер экспортирует инструменты по «голым» именам (например, `get_user_info`, `create_project`). Разные хост-агенты могут добавлять префикс — например, Claude показывает их как `mcp__sape__get_user_info`. Этот навык обращается к инструментам по **«голым» именам**; используйте ту форму, которую ожидает ваш агент.

Инструмент `authorize` присутствует на сервере, но запускается автоматически — вызывать его вручную не нужно. Сервер сам обновляет токены.

## Проверка подключения

Прежде чем делать что-либо ещё, вызовите `get_user_info`. Если возвращается `balance` (а также `login`/`email`) — MCP подключён и аутентифицирован. Верхнеуровневое поле `balance` — доступный остаток на счёте в валюте пользователя (`userWmPriorityCurrency`). Чтобы пополнить баланс, направьте пользователя на [https://passport.sape.ru/deposit/](https://passport.sape.ru/deposit/) — не пытайтесь пополнять счёт программно.

## Доменная модель

Понимание этих сущностей проясняет остальной workflow:

- **Проект (Project)** — контейнер для всего перечисленного ниже. Создаётся под конкретный домен, хотя внутри можно продвигать и другие домены. **Общий** для статейных и арендных размещений.
- **URL** — продвигаемая страница, на которую ведут размещения. Привязан к проекту. **Общий.**
- **Статья (Article)** — полная HTML-статья, загруженная рекламодателем для формата `news`. Проходит модерацию, поэтому имеет статус. Привязана к проекту.
- **Текст (Text)** — анкорный текст, используемый в ссылке. При загрузке Статьи Текст и URL создаются автоматически. URL-ы и Тексты можно также добавлять вручную через `add_texts` — так вы добавляете дополнительные продвигаемые страницы и анкоры для форматов, где контент пишет вебмастер (`review`, `link`, `archive`, `rent`). **Общий.**
- **Контент (Content)** — общий термин для Статьи и Текста, у каждого свои переходы статусов.
- **Размещение (Placement)** — купленная ссылка. Бывает двух типов:
  - **Статейное** — разовая оплата, сложный жизненный цикл (модерация, проверка, арбитраж).
  - **Арендное** — помесячная оплата, упрощённый жизненный цикл (активно → заморозка → удаление). Привязано к Тексту и URL.

## Типы размещений и их различия

| Аспект             | Статейные                                                         | Арендные                                                        |
|--------------------|-------------------------------------------------------------------|-----------------------------------------------------------------|
| **Оплата**         | Разовая                                                           | Ежемесячная (рекуррентная)                                      |
| **База доноров**   | Общая для всех форматов                                           | Отдельная                                                       |
| **Жизненный цикл** | Сложный: модерация → размещение → проверка → арбитраж → одобрение | Простой: создание → одобрение → активно → заморозка/удаление    |
| **Поиск**          | `search_sites` по `project_id`                                    | `search_rent_sites` по `url_id`                                 |
| **Покупка**        | `purchase_placement` по `site_id`                                 | `purchase_rent_placement` по `page_id` + эхо-значения из поиска |
| **Срок жизни**     | Бессрочно (разовая оплата)                                        | Пока оплачивается; при нулевом балансе — замораживается         |

### Форматы

#### Статейные (разовая оплата)

| Формат в виде кода | Формат для человека | Контент предоставляет       | Обязательно для покупки | Примечания                                                  |
|--------------------|---------------------|-----------------------------|-------------------------|-------------------------------------------------------------|
| `news`             | Статья              | Рекламодатель (клиент)      | `article_id`, `url_id`  | `text_id` не нужен — статью полностью предоставляет клиент. |
| `review`           | Обзор               | Статья вебмастера           | `url_id`, `text_id`     | Вебмастер пишет обзорную статью. **Дороже.**                |
| `link`             | Ссылка в новости    | Вебмастер                   | `url_id`, `text_id`     | Вебмастер органично встраивает ссылку в новостной материал. |
| `archive`          | Ссылка в архиве     | Н/А (статья уже существует) | `url_id`, `text_id`     | Ссылка размещается в уже опубликованной статье.             |

#### Арендные (помесячная оплата)

| Формат | Контент предоставляет | Обязательно для покупки | Примечания                                                                                                                     |
|--------|-----------------------|-------------------------|--------------------------------------------------------------------------------------------------------------------------------|
| `rent` | Вебмастер             | `url_id`, `text_id`     | Арендная ссылка (Niche Edit). Вебмастер размещает ссылку на существующей странице своего сайта. **Цена указывается за месяц.** |

## Рабочий процесс

### 1. Создайте проект для продвигаемого сайта

```
create_project(domain="example.com")
```

Передавайте домен **без** `https://`. Сохраните возвращённый **id** проекта (`PROJECT_ID`) — он понадобится везде. При создании проекта также автоматически создаются один **URL** (сам домен) и один Текст по умолчанию.

Чтобы увидеть существующие проекты вместо создания нового:

```
list_projects()
```

Возвращает `projectsInGroupList[]`, где каждая запись содержит `id` (`PROJECT_ID`), `domain`, `name` и `firstUrlId` (id авто-созданного URL — удобно, когда нужен `url_id`).

Все аргументы опциональны. Используйте их для пагинации, сортировки и фильтрации:

```
# Страница 2, 50 проектов на страницу, новые сверху
list_projects(page=2, limit=50, order_by="byCreatedAt", order_type="desc")

# Только активные проекты, отсортированы по имени
list_projects(project_filter="isActive", order_by="byProjectName")

# Получить конкретные проекты по ID
list_projects(projects_ids=[123, 456])
```

| Аргумент         | Значения                                                                                              | Описание                         |
|------------------|-------------------------------------------------------------------------------------------------------|----------------------------------|
| `page`           | `1+`                                                                                                  | Номер страницы (с 1)             |
| `limit`          | `20`, `50`, `100`, `250`                                                                              | Проектов на страницу             |
| `order_by`       | `byProjectName`, `byLinksCount`, `byUrlsCount`, `byAutobuyersCount`, `byMonthlyBudget`, `byCreatedAt` | Поле сортировки                  |
| `order_type`     | `asc`, `desc`                                                                                         | Направление сортировки           |
| `project_filter` | `all`, `isActive`, `isArchived`, `withErrors`                                                         | Фильтр по статусу                |
| `projects_ids`   | `[id, …]`                                                                                             | Фильтр по конкретным ID проектов |

> **Поиск по имени?** API не поддерживает поиск по подстроке. Отсортируйте по `order_by="byProjectName"` и отфильтруйте результаты на клиенте, либо используйте `projects_ids`, если знаете ID.

### 2. Подготовьте контент

Для формата `news` статью необходимо загрузить **до** покупки. Статью проверяют модераторы Sape; покупать можно только статьи в статусе `approved`.

```
add_article(
  project_id=PROJECT_ID,
  url="https://example.com/landing-page",
  title="Внутренний заголовок статьи",
  meta_title="Мета-заголовок для вебмастера",
  body="<p>HTML-статья с уже вставленной <a href='https://example.com'>ссылкой</a>.</p>"
)
```

- `url` — полный URL продвижения, включая `https://`.
- `title` — только внутренний (виден в интерфейсе Sape).
- `meta_title` — используется вебмастером при публикации.
- `body` — HTML-контент с уже вставленными ссылками (должен содержать минимум одну). Максимум 64 000 символов.

Вызов возвращает `articleId` и `urlId`. Модерация обычно занимает 1–2 рабочих дня. Если статью отклонили — прочитайте причину и загрузите исправленную версию.

Проверка статуса контента:

```
get_project_content_list(project_id=PROJECT_ID)
```

Для форматов `review`, `link`, `archive` и `rent` **статья не нужна** — покупка использует `url_id` и `text_id`, а окружающий контент пишет вебмастер.

#### Добавление URL-ов с анкорами (`add_texts`)

Для форматов, где контент пишет вебмастер, продвигаемый URL и анкор передаются через `add_texts`. Так вы добавляете страницы помимо авто-созданного URL домена и анкоры помимо дефолтного.

```
add_texts(
  project_id=PROJECT_ID,
  urls_texts=[
    {
      url: "https://example.com/blog/seo-guide",
      texts: [
        {text: "См. наш #a#полный SEO-гайд#/a# подробнее"},
        {text: "Узнайте больше о #a#линкбилдинге#/a#"}
      ]
    },
    {
      url: "https://example.com/services/",
      texts: [{text: "Профессиональные #a#SEO-услуги#/a#"}]
    }
  ]
)
```

- `url` — полный URL продвижения, включая `https://`.
- `texts[].text` — анкорный текст. Разметка `#a#...#/a#` помечает фрагмент, который станет ссылкой. У одного URL может быть несколько анкоров (каждый станет отдельным `text_id`).
- `keywords` (опционально) — ключевые фразы, по которым вебмастер будет писать контент.

Вызов возвращает `texts[]` с `urlId` и `textsList` (массив ID текстов) для каждого URL, а также `urlErrors`/`textErrors`, если валидатор отклонил URL или анкор.

**Когда что использовать:**

| Нужно                                                        | Инструмент    |
|--------------------------------------------------------------|---------------|
| Полная статья рекламодателя (формат `news`)                  | `add_article` |
| Только URL + анкоры (`review` / `link` / `archive` / `rent`) | `add_texts`   |

### Путь А. Статейные размещения (разовая оплата)

#### 3a. Поиск площадок-доноров

```
search_sites(project_id=PROJECT_ID, link_type="link")
```

Допустимые значения `link_type`: `news`, `review`, `link`, `archive`. Результат — список подходящих доноров со сводными метриками.

Распространённые фильтры для сужения поиска:

- `language` — язык площадки
- `price_from`, `price_to` — диапазон цены
- `ahrefs_dr_from`, `ahrefs_dr_to` — Ahrefs Domain Rating
- `moz_da_from` — Moz Domain Authority; `moz_spam_score_to` для ограничения спама
- `majestic_cf_from`, `majestic_tf_from` — Majestic Citation / Trust Flow
- `traffic_ahrefs_from`, `traffic_semrush_from` — объём трафика
- `pages_google_from` — минимум страниц в индексе Google
- `domain_level` — `0` все, `2` только второго уровня, `3` только третьего
- `days_old_whois_from` — минимальный возраст домена в днях
- `external_links_to` — ограничение внешних ссылок на странице-доноре
- `avg_placement_time_from` / `avg_placement_time_to` — окно скорости размещения
- `placement_probability_from` — минимальная вероятность размещения (%)
- `keywords` — ключевые фразы через запятую
- `site_url` — ограничение конкретной площадкой-донором

Полные детали (цена, DR, трафик, язык, примеры размещений) по кандидату:

```
get_site_info(site_id=SITE_ID)
```

#### 4a. Покупка размещения

**Стоп. Сначала прочтите финансовые ограничения.** Никогда не вызывайте `purchase_placement` без явного подтверждения пользователя.

Когда есть всё необходимое:

- `PROJECT_ID`
- `SITE_ID` (из результатов поиска)
- Для `news`: статья в статусе **approved** (`article_id`) и `url_id`
- Для `review` / `link` / `archive`: `url_id` и `text_id` (из `add_texts` или авто-созданных дефолтов при создании проекта)
- `search_history_id` — всегда передавайте **пустую строку** `""`

Примеры по форматам:

```
# news — статья рекламодателя
purchase_placement(project_id=PROJECT_ID, link_type="news",
  site_id=SITE_ID, article_id=ARTICLE_ID, url_id=URL_ID, search_history_id="")

# review — статья вебмастера
purchase_placement(project_id=PROJECT_ID, link_type="review",
  site_id=SITE_ID, url_id=URL_ID, text_id=TEXT_ID, search_history_id="")

# link — In The News (Link Insertion)
purchase_placement(project_id=PROJECT_ID, link_type="link",
  site_id=SITE_ID, url_id=URL_ID, text_id=TEXT_ID, search_history_id="")

# archive — In The Archive (Link Insertion)
purchase_placement(project_id=PROJECT_ID, link_type="archive",
  site_id=SITE_ID, url_id=URL_ID, text_id=TEXT_ID, search_history_id="")
```

Опционально для любого формата: `is_content_need_approval=true` — размещение ждёт одобрения рекламодателя, прежде чем вебмастер начнёт работу. Полезно, когда нужно проверить финальный контекст.

### Путь Б. Арендные ссылки (помесячная оплата)

Арендные ссылки (Niche Edits) используют **отдельную базу доноров** и оплачиваются **помесячно**. Поиск и покупка отличаются от статейных размещений.

#### 3б. Поиск арендных доноров

Арендный поиск идёт по конкретному **URL** (не по проекту) и работает асинхронно — инструмент `search_rent_sites` внутренне запускает поиск и опрашивает результат, возвращая готовые данные.

```
search_rent_sites(url_id=URL_ID)
```

Распространённые фильтры (все опциональны):

- `price_rent_from`, `price_rent_to` — диапазон **месячной** цены
- `yandex_sqi_from`, `yandex_sqi_to` — Yandex SQI (ИКС)
- `ahrefs_dr_from`, `ahrefs_dr_to` — Ahrefs Domain Rating
- `moz_da_from`, `moz_da_to` — Moz Domain Authority
- `moz_spam_score_from`, `moz_spam_score_to` — Moz Spam Score
- `majestic_cf_from`, `majestic_cf_to` — Majestic Citation Flow
- `majestic_tf_from`, `majestic_tf_to` — Majestic Trust Flow
- `traffic_ahrefs_from`, `traffic_semrush_from`, `traffic_yandex_from` — объём трафика
- `semrush_as_from`, `semrush_as_to` — Semrush Authority Score
- `ahrefs_backlinks_from`, `ahrefs_keywords_from` — бэклинки и ключи Ahrefs
- `nof_pages_google_from`, `nof_pages_yandex_from` — страницы в индексе
- `domain_level` — `0` все, `2` второго уровня, `3` третьего
- `site_languages` — языки площадок (список, например `["ru", "en"]`)
- `keywords` — ключевые фразы через запятую
- `external_links_to` — максимум внешних ссылок на странице
- `avg_placement_time_from` / `placement_probability_from` — скорость и вероятность размещения
- `is_credit_available` — `0` все, `1` только с кредитом, `2` только без

**Структура ответа** — сохраните эти значения, они нужны для покупки:

```
data:
  searchId: 999              ← эхо-значение для purchase_rent_placement
  forceSeoWait: 0            ← эхо-значение
  mosSites: "Yw=="           ← эхо-значение
  pagesExtra: ""             ← эхо-значение
  nofResultsTotal: 42
  resultList:                ← найденные сайты-доноры
    - id: 100500             ← ID сайта
      url: "example-donor.ru"
      priceFrom: 30           ← минимальная цена за месяц
      pages:                  ← доступные страницы для покупки
        - id: 312456          ← pageId для purchase_rent_placement
          url: "example-donor.ru/article"
          price: 45            ← цена за месяц
          nofExternalLinks: 3
```

> **Важно:** значения `searchId`, `forceSeoWait`, `mosSites`, `pagesExtra` устаревают после покупки — для новой партии ссылок нужен новый поиск.

#### 4б. Покупка арендных ссылок

**Стоп. Сначала прочтите финансовые ограничения.** Арендная ссылка — это **рекуррентный платёж**: сумма списывается каждый месяц, пока ссылка активна.

```
purchase_rent_placement(
  project_id=PROJECT_ID,
  search_id=SEARCH_ID,        # из data.searchId
  force_seo_wait=FORCE_SEO_WAIT,  # из data.forceSeoWait
  mos_sites=MOS_SITES,        # из data.mosSites
  pages_extra=PAGES_EXTRA,    # из data.pagesExtra
  pages=[
    {page_id: 312456, url_id: URL_ID, text_id: TEXT_ID},
    {page_id: 312457, url_id: URL_ID, text_id: TEXT_ID}
  ]
)
```

- `pages` — список страниц для покупки. Можно купить **несколько страниц за один вызов**.
- `page_id` — ID страницы-донора из `data.resultList[].pages[].id`.
- `url_id` и `text_id` — продвигаемый URL и анкор из проекта (получены через `add_texts` или авто-созданы).
- `force_seo_wait` управляет поведением на сайтах с авто-приёмом:
  - `0` — подтверждать с открытыми URL, закрытые отправлять в заявки
  - `1` — отправлять все в заявки
  - `2` — подтверждать все (открытые и закрытые)

В ответе: `placements[]` с `placementId` для каждой купленной ссылки и `errors[]` при неудачах (например, `isNotEnoughMoney: true`).

Просмотр купленных размещений (общий для статейных и арендных):

```
get_project_placements(project_id=PROJECT_ID)
```

### 5. Управление размещениями

После покупки каждое размещение движется по статусному workflow. Жизненный цикл арендных ссылок **проще**, чем статейных. Влияйте на статус массовыми действиями:

```
perform_placement_action(placement_ids=[PLACEMENT_ID], action="approve_seo")
```

`placement_ids` — это **список** (можно действовать сразу по нескольким). `action` — одно из SEO-действий, описанных в **`references/placement_actions.md`**.

**Прочитайте `references/placement_actions.md` перед любым действием над размещением.** Действия различаются для статейных и арендных размещений — одни и те же имена действий (например, `terminate_seo`) работают по-разному. Некоторые действия передают средства вебмастеру или приводят к потере денег.

#### Особенности арендных размещений

- **`approve_seo`** — одобряет созданную авторежимом ссылку (из `STATUS_NEED_APPROVE` → `STATUS_APPROVED`).
- **`terminate_seo`** — немедленно удаляет арендную ссылку (→ `STATUS_TERMINATED`). Для статейных сначала переводит в `STATUS_TO_TERMINATE`.
- **`sleep_manual_seo`** — замораживает ссылку (→ `STATUS_SLEEP_MANUAL`). Списание приостановлено.
- **`unsleep_manual_seo`** — размораживает ссылку (→ `STATUS_APPROVED`). Требует достаточный баланс.
- **`order_change_links_texts_seo`** — запрашивает смену текста активной ссылки (→ `STATUS_CHANGE_REQUESTED`).
- **`force_billing_seo`** — досрочная оплата (не путать с разморозкой).

## Финансовые ограничения

Это не бюрократия — каждая покупка и ряд действий с размещениями двигают **реальные деньги**, а ошибки трудно или невозможно отменить. Относитесь соответственно.

**Перед `purchase_placement` (статейные):**

1. Вызовите `get_user_info` и прочтите текущий `balance`.
2. Вызовите `get_site_info(site_id=SITE_ID)` и прочтите цену выбранного донора.
3. Покажите пользователю: URL площадки и цену, текущий баланс и **остаток после покупки** (balance − price).
4. Запросите **явное подтверждение**. Покупайте только после согласия.

**Перед `purchase_rent_placement` (арендные):**

1. Вызовите `get_user_info` и прочтите текущий `balance`.
2. Покажите пользователю **месячную стоимость** каждой выбранной страницы и общую сумму.
3. Объясните, что это **рекуррентный платёж** — сумма будет списываться каждый месяц до удаления ссылки.
4. Покажите, на сколько месяцев хватит баланса при текущем уровне расходов.
5. Запросите **явное подтверждение**. Покупайте только после согласия.

> **Критично для арендных:** при недостатке баланса ссылки **замораживаются** (`STATUS_SLEEP_BILLING`), а не удаляются. Они перестают работать, но возобновляются после пополнения. Следите за балансом.

**Перед `perform_placement_action`:**

1. Объясните, что делает действие и его финансовые последствия. В частности:
   - `approve_seo` / `approve_content_seo` — передают средства вебмастеру.
   - `cancel_seo` / `cancel_from_*` — может инициировать возврат или потерю средств.
   - `terminate_seo` — для арендных: немедленно удаляет ссылку и прекращает списания; для статейных: инициирует снятие.
   - `sleep_manual_seo` — приостанавливает списания по арендной ссылке.
   - `unsleep_manual_seo` — возобновляет списания.
   - `approve_from_arbitration_seo` — решает спор в пользу рекламодателя.
2. Запросите **явное подтверждение**. Действуйте только после согласия.

Если пользователь не подтверждает — не продолжайте. Подождать — нормально.

## Чек-лист перед покупкой

Прогоните перед покупкой — это ловит почти все частые ошибки:

### Статейные размещения

- [ ] `PROJECT_ID` известен (создан или найден через `list_projects`)
- [ ] Для `news`: статья в статусе `approved` (`get_project_content_list`)
- [ ] `SITE_ID` выбран, с приемлемыми метриками (`get_site_info`)
- [ ] `url_id` (и `text_id` для `review`/`link`/`archive`) известны — добавьте ещё через `add_texts` при необходимости
- [ ] `search_history_id` равен `""`
- [ ] Баланс покрывает цену, и пользователь явно подтвердил

### Арендные размещения

- [ ] `PROJECT_ID` известен
- [ ] `URL_ID` известен (авто-созданный `firstUrlId` при создании проекта, или из `add_texts`)
- [ ] Поиск выполнен через `search_rent_sites` — эхо-значения (`searchId`, `forceSeoWait`, `mosSites`, `pagesExtra`) сохранены
- [ ] `text_id` известен
- [ ] Выбранные `page_id` из результатов поиска
- [ ] Пользователь понимает, что цена — **за месяц**, и подтвердил рекуррентное списание

## Устранение неполадок

- **«Моя статья недоступна»** — вероятно, ещё на модерации. Проверьте статус через `get_project_content_list`; покупать можно только статьи в `approved`. При отклонении обычно указывается причина — исправьте и загрузите заново.
- **«Недостаточно средств»** — проверьте через `get_user_info` (`balance`). Направьте пользователя на [https://passport.sape.ru/deposit/](https://passport.sape.ru/deposit/) для пополнения. Не пытайтесь добавлять средства через API.
- **«Арендная ссылка заморожена» (SLEEP_BILLING)** — недостаточно средств на балансе. Ссылка приостановлена, но не удалена. Пополните баланс — ссылка разморозится автоматически. Для ручной разморозки используйте `unsleep_manual_seo`.
- **«Арендный поиск не завершился»** — `search_rent_sites` опрашивает результат до ~150 секунд. Если вернулся `_timed_out: true`, просто повторите вызов.
- **«Размещение застряло»** — сверьте текущий статус с таблицей в `references/placement_actions.md`; она подскажет, какие действия доступны из каждого статуса и какие таймауты действуют.
- **Ошибки MCP/авторизации или 401** — сервер обновляет токены автоматически. Если ошибки сохраняются, обычно помогает переподключение Sape Links MCP в настройках хост-агента.
- **«Сколько размещений требуют внимания?»** — `get_user_info` возвращает `seoCounters`, например `nofLinksStatusNeedApprove`, `nofPlacementCheck`, `nofPlacementsContentOnApproval`, `nofClarification`. Используйте их, чтобы подсветить требующее действия.
